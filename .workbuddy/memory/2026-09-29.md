## 追加：第三轮交互需求（分类栏固定新增入口 / 拖动排序 / 跨象限拖 / 置顶置底）

用户要三件事：① 分类栏分类一多，「+ 新增」被挤出屏幕；② 象限详情要能拖动排序，
左滑再加「置顶 / 置底」；③「全部」页也要能拖，且能拖到别的象限里去，但不显示置顶置底。

### 1. 分类栏

结构从「一个 scroll-view 装所有胶囊 + 新增按钮」改成 `.catsrow`（flex）包两层：
左侧 `.cats{flex:1;min-width:0}` 自己横向滚动，右侧 `.cats-add` 固定 60rpx 一列。
**`min-width:0` 是关键**——flex item 默认 `min-width:auto`，不清掉它左侧根本滚不起来。
原 `.cat.add` 规则随之删除。

### 2. 手势契约（重要，别再混）

| 手势 | 结果 |
|---|---|
| 横向滑动 | 左滑露出操作（详情 4 个 / 全部 2 个） |
| 长按 ~350ms 不动 | 拿起卡片拖排序 |
| 点 | 进编辑抽屉 |

用长按而非「按下即拖」：整屏都是卡片，按下即拖会让列表再也滚不动。
`onRowLong` 里先检查 `this._moved`，已横向滑动就拒绝进入拖动。

### 3. 拖动实现的三条 setData 通道

- `dragY`：被拖卡片跟手位移，每个 touchmove 都变，但**只推一个数字**；
- `shift`：其余卡片的让位量，**只在跨过某行中线时才变**（此时才 setData 整个 rows/sections）；
- 行位置在「拿起」时用 `boundingClientRect` 量**一次**，之后不再查询。

配套：拖动期间 `scroll-y="{{!dragOn}}"` 关掉列表滚动，否则悬浮卡片与背景行对不上。
拖动中的卡片要挂到 `.row` 上的 `liftrow`（解除 `overflow:hidden` + 抬 z-index），
否则会被自己那一行裁掉。

### 4. 排序落库：整段重写 0/10/20…，只发变化的

`commitOrder(lists)` 把受影响象限重排成 `i * ORDER_STEP`，只把 `order` 或 `quad`
真正变了的行发给新增的云函数 action `reorder`（逐条校验 `_openid`，单次上限 200）。
不用「相邻取中值」是因为反复拖动会把浮点间距耗光，collapse 后还得重排。

### 5. 筛选下的拖动语义（易错点）

详情页有 全部/待办/已完成 三个筛选。**只重排可见项，隐藏项原地不动**，
靠 `visibleIdx(full)` 把「可见列表下标」映射回「完整列表下标」再 splice。
否则筛到「待办」时一拖动就会把已完成的项挤走。置顶/置底同理：只排到可见列表的首/尾。

### 6. 跨象限拖（仅「全部」页）

`flatList()` 把分段展开成扁平数组，`.row` 的测量顺序与它一一对应（不一致就放弃本次拖动）。
`flat[to].sec !== flat[from].sec` 即跨象限：**不做让位动画**（各行高度不一，硬算必错位），
改为整段高亮 + 「松手移到这里」，松手后改 `quad` 并重排源/目标两个象限。

### 7. 边界 bug（测试里抓到的）

位移被夹在列表首尾之内，拖到最上/最下那一档的瞬间，卡片中心**正好等于**首/尾卡片中线，
用严格大于会永远差一档（表现为「怎么拖都放不到第一位/最后一位」）。
换位判定加了 `EPS = 0.5` 容差。

### 8. 新增测试资产

`.workbuddy/tools/test-reorder.js` —— 用假的 `Page` / `wx` 环境**加载真实 index.js**，
跑真实方法（不复制逻辑）。11 组 / 38 条断言，覆盖同象限换位、带筛选的隐藏项、
跨象限搬运、拖回原位不落库、置顶置底幂等、让位位移、跨段高亮、拖动几何与边界容差。
`node .workbuddy/tools/test-reorder.js`，失败返回码非 0。

**验证**：两个 JS + 测试文件 `node --check` 通过；mp-check 三项全绿
（WXML 145 类 / WXSS 149 类 / data 47 键，结构配对 244/244 · 188/188 · 334/334）；
仿真测试 38/38。真机行为待用户验证。

**已知限制**（写进 README 第七节）：拖动过程中不自动滚动（目标行要先滚进视野）；
拖动期间列表不可滚，松手恢复。

## 第九轮：长列表「滑动时卡片消失」

用户反馈：`列表多的时候，我滑动到的块都消失了`，附一张排序模式下的截图。

### 量图：先确认「消失」是什么形态

截图 578×1225（手机屏区 x28..548，1rpx≈0.693px）。逐行扫非底色内容：

| 区域 | 实测 | 含义 |
|---|---|---|
| y346..386 | 三条半透明白胶囊 | 固定头部的筛选行（最后一块固定内容） |
| y392..407 | 全宽白块，**上边平、下边两角圆** | 被滚动区顶边裁掉的一行卡片（只露底部 17px） |
| y418..586 | 完整白卡 + 下方阴影 | 第二行卡片 |
| y586..1102 | **纯底色，一个像素都没多** | 第三行起的卡片全部没有绘制 |
| y1102.. | 白底 + 蓝色「完成」 | 排序模式固定底栏 |

按行高 134px / 间距 11px 反推：scrollTop ≈ 117px，第二行的顶部正好落在 y=418（实测 418 ✓）。
**所以内容高度 ≥ 827px（至少 5 行），但只有前两行被画出来** —— 数据里有 7 行（头部「7 项待办」、
筛选「全部 7」都指同一份 `inQuad`），布局空间也占着，就是不上屏。

### 根因：一个「僵尸拖动」+ 手势中途改 scroll-y

1. `startDrag()` 里 `measureRows()` 的回调是**异步**的，而它无条件写 `that._dg`。
   手指点一下就抬走（或中途切视图）时，回调迟到 → `_dg` 被装上但**再也没人清**。
2. 于是此后**每一次 touchmove 都会被 `onRowMove` 开头的 `if (this._dg)` 吃掉**，
   走 `applyDragMove`：用**滚动之前**量到的行位置去算 `dy` 与目标下标，
   `paintDrag` 把整个 `rows` 数组重新 `setData` 一遍（带让位位移）。
3. 与此同时 `scroll-y="{{!dragOn}}"` 是「手指一动才关」——滚动由视图层在 touchmove
   那一刻就启动，`setData` 关得晚半拍：列表滚了、卡片又在重排，两边打架。
   两者叠加 = 滚动过程中内容反复重排 + 图层重绘跟不上 → 后半个列表空白。
   （截图里 scrollTop=117 也证明排序模式下确实滚过。）

### 修法（四刀）

| # | 改动 | 说明 |
|---|---|---|
| 1 | `_dragSeq` 代号 + 三道闸 | `measureRows` 回调里校验「代号未变 + 仍在拖动中 + 同一行」，否则丢弃。这是**真 bug 的修复** |
| 2 | `onRowEnd` 排序模式分支补清 `dragId/dragY` | 手指点一下就抬走时，`dragId` 已推到视图层而 `_dg` 还空，只清 `dragOn` 会让那张卡一直挂着抬起阴影 |
| 3 | `onSortToggle()` / `exitSort()` 一并清 `_dg`+`_drag` | 切模式 / 切视图时不留僵尸 |
| 4 | `scroll-y` 改绑 `sortMode` | 进模式时一次性关掉列表滚动，手势中途不再改配置 |

外加两条「少造图层」的视图层改动（长列表滚动的重绘余量）：

- **静止的行不挂 transform**：行位移在 WXML 里改成条件渲染，静止时写 `none`，
  不再输出 `translateX(0) translateY(0)`。transform 会让每个行元素被提升成独立图层，
  长列表里几十层叠着，滚动时新暴露的区域来不及重绘。
- **`.row` 不再常驻 `overflow:hidden`**：裁剪只为「滑开时把操作面板按圆角裁掉」服务，
  改成只在 `swipeKey===_id` 的那一行挂 `.row.sw`。少一层裁剪层。

```

class 重名扫描     OK
test-reorder      17 组 / 100 条全通过   ← 新增 [14] 竞态、[15] 视图层防回归
test-cloudfn      48 条全通过
JSON              10 个全部合法
```

新增的第 [14] 组用**可挂起的 `createSelectorQuery` 桩**复现竞态（`measureDeferred` +
`flushMeasure()`），并且做了**反向对照**：手动装一个僵尸 `_dg`，同一个「滚动」手势立刻
就会整表重排 `rows` —— 证明这组断言真能抓到它，不是写了也永远绿。
第 [15] 组是静态断言：全页只允许一处内联 transform 且必须是条件渲染、`scroll-y` 必须绑
`sortMode`、`.row` 不得常驻裁剪、`.row.sw` 必须存在。

### 沉淀

- 竞态排查套路：**凡是「异步回调里写共享状态」，都要有代号/有效性校验**。
  这类 bug 在单次同步测试里永远绿，必须让桩支持「回调迟到」。
- 视图层成本：滚动容器里**别给静止元素挂 transform / 裁剪**。为了动画方便而让所有
  行都带 `transform`，代价是每个行一个图层。
- 排序模式的滚动：手势中途改 `scroll-y` 不可靠（滚动在视图层先启动）。
  要「能滚动 + 能拖动」两全，正确做法是拖动把手独立成 `catchtouchmove` 的区域，
  而不是靠抢手势。当前先按「排序模式不滚动」处理，已写进 README 的已知限制。
  → **第 10 轮的当天下午就按这个方案落地了，见下。**

## 第十轮：三处 UI 调整（提示行对齐 · 排序模式可滚动 · 统计块居中）

### 用户报的三件事

1. 「向左滑动…」那行提示是居中的，希望跟上面「拖动卡片…」一样左对齐；
   「调整顺序」按钮在同一行，一起调。
2. 「点了调整顺序就没法滚动了，能不能优化成可以滚？不行就说明原因。」
3. 「我的」页上面四个统计块的标题、文案没有上下居中。

### 第 1 件：提示行左对齐

`.swipecue` 原本 `text-align:center`。加 `.swipecue.left { text-align:left; padding:0 32rpx }`，
32rpx 与 `.sortrow` 的左内边距对齐；详情页与全部页那两条挂 `.left`，
**总览页那条「矩阵按重要性 × 紧急性排列」不挂**，保持居中（语义不同）。

### 第 2 件：排序模式可滚动（本轮重点）

**之前为什么不能滚**：拖动与滚动都是纵向手势。早先整张卡片都能拖，两者抢同一串
`touchmove`，只能靠关掉 `scroll-y` 给拖动让路 —— 代价是排序模式完全滚不动。

**能做，按上一轮预言的方案落地**：

- 卡片右侧加 `.dh` 手柄（仅排序模式渲染），`catchtouchstart/catchtouchmove/catchtouchend`
  —— 事件不再冒泡到 scroll-view；
- 卡片本体仍是 `bind`，事件照常交给 scroll-view → **排序模式下正常滚动**；
- 再加**边缘自动滚**：手指进入滚动区上下缘 96px 内，每 40ms 滚 14px，
  长列表才够得着屏幕外的落点。

`onHandleStart/Move/End` 直接复用 `onRowStart/Move/End`，只在 `_drag` 打一个 `handle` 标记，
`onRowMove` 的排序模式分支改成 `if (!this._drag || !this._drag.handle) return;` —— 一份状态机没分叉。

难点全在「列表滚起来之后坐标会漂」：

| 坑 | 修法 |
|---|---|
| 卡片用 translateY 相对「自己那一行的当前位置」定位，而行会随列表滚 | 位移公式改成 `base0 + (clientY - _dgY0) - rects[from].top`，`base0` = 拿起时的 `rects[from].top`。列表没滚时正好退化成 `clientY - _dgY0` |
| 换位判定用的行位置是过期的 | `bindscroll` 报来真实滚动量，`_dg.rects` 整体减去它；手滚 / 自动滚共用同一条回路 |
| `minDy/maxDy` 要不要跟着滚重算 | 不用。它只描述「首尾相对被拖卡片」，滚动时同减同增、是常量 |
| 自动滚怎么知道滚到头了 | `setData({scrollTop})` 之后**不能立刻**判断（bindscroll 是异步回来的）→ 放到**下一拍开头**比 `_scrollTop === dg.asPending` |
| 贴着尽头一直 setData | 记 `asDirDone`；手指移动 > 4px 才清掉它、并清 `asPending`（不清会假阳性判成「没动」） |

定时器用 `setTimeout` 自串（不用 `setInterval`）：手指离开边缘后下一拍自然就停，
不必去 clearInterval。`endDrag` / `exitSort` / `onRowEnd` 都调 `stopAutoScroll()`。

`scroll-y` 从此**常开**，任何模式的任何时刻都不动它。

### 第 3 件：统计块上下居中

`.stat` 是 `.stats`（flex）的子项，默认 `align-items:stretch` → 被拉到 112rpx 高，
而「数字 + 标题」只有 62rpx。总览页 `.stats` 有 `padding-top:24rpx` 垫着，看不出来；
「我的」页 `.stats.flat` 把内边距清零，多出来的 26rpx 全落在下面 → 整块贴顶。
`.stat` 改成 `display:flex;flex-direction:column;align-items:center;justify-content:center`。
**`text-align:center` 只管左右，管不了上下。**

### 沉淀

- **两种纵向手势落在同一个元素上必然互斥**，唯一正解是把它们分到不同元素
  （`catch` vs `bind`）。靠改 `scroll-y` 去抢是抢不赢的：滚动由视图层在 touchmove
  那一刻先启动，`setData` 关得晚半拍。第 9 轮已经猜到解法，第 10 轮落地。
- **异步 API 的桩要按真实返回结构写**。`select` 单点的 `res[0]` 是 rect，
  `selectAll` 的 `res[0]` 才是 rect 数组。我第一版写错，页面一直走「量不到滚动区」的
  降级分支，而测试「看起来」通过了 —— 因为降级本身是合法行为，断言又没覆盖正向路径。
  教训：**降级路径要有正反两组断言**，只测「不崩」等于没测。
- **`setData` 之后紧接着读回同一份状态来判断「生效没有」永远是错的**，
  异步生效的东西必须等下一拍。

## 第十一轮：共享家庭 v3（数据归属从「人」改为「家庭」）

### 需求与决策

用户提出：进小程序默认有一个「家庭 id」，家底下的待办归家庭所有；若加入别人的家庭，
就能读写对方家庭的全部事项。经三问确认：**现在就改 / 完全共享（可读可写）/ 要实时自动同步**。

这不是小改动，是 v3 迭代：**数据归属键由 `_openid` 换成 `fid`**，牵动 9 个 action 的过滤条件、
两张新集合、我的页新 UI 卡片、以及一整套越权防护测试。

### 安全模型（铁律）

1. **`fid` 只由服务端推导，绝不接受客户端入参。** 云函数用管理员权限跑，天然绕过数据库安全规则，
   一旦允许前端传 `fid`，等于把任意家庭的读写口子敞开。`ensureFamily(OPENID)` 从 `fq_members`
   反查当前活跃家庭，前端传什么都无视（测试 [12] 专测这条）。
2. **客户端永不直连数据库**，读写一律走云函数 —— 所以放弃 `watch()`，改用 8 秒轮询。

### 同步方案

- 每个家庭一个 `rev` 版本号，写操作 `bumpRev()`（`db.command.inc`）。
- `sync` 行动作：入参带本地 `rev`，相等即返回 `{changed:false,rev}`（省一次全量传输），
  不等才回全量 + 家庭信息。`SYNC_MS = 8000`。
- **三条让步条件**，避免「刚点完就被同步刷回去」：`sortMode`（正在排序）、`sheetOpen`（抽屉开着）、
  `pendingWrites > 0`（有写在途）任一成立就跳过本轮。
- `pendingWrites` 在 `callCloud` 里增减，**成功和失败两条路径都要递减**，否则一次失败就永久停摆。

### 邀请码流程

6 位码，24h 有效，**只回传给 owner**；归一化大小写与空格。分享卡片路径
`pages/index/index?code=XXXXXX`，被邀请者一进来自动入伙（`handlePendingInvite`）。

### 老数据迁移

v3 之前的数据只有 `_openid` 没有 `fid`。`createDefaultFamily()` 首次进入时把「只有 `_openid`」的
宽松文档补上 `fid`，**不重新播种**；分类数为 0 才 seed。

### 已知取舍

完全共享 + 8 秒轮询在「两人同时编辑同一条」时是后写覆盖先写，没有冲突合并。
真要做到无冲突，得自定义数据库安全规则 + `watch()`，那是下一步的事，README §十一 已写明。

### 沉淀

- **权限提升型云函数里，凡是「归属键」都必须服务端推导。** `_openid` 之所以安全是因为
  运行时注入、前端改不了；换成 `fid` 后这条保障就没了，必须自己补回来 —— 前端传的归属键
  一律当脏数据丢弃。
- **「实时同步」和「不直连数据库」是一对矛盾**，轮询是保住边界的折中解。业务要实时，
  别急着开 `watch`，先问这句：数据库安全规则能不能表达「只读自己家庭」？不能就别开。
- **测试里出现「看起来通过但没测到正向路径」是最大的坑**（第 10 轮已踩过一次）。
  本轮加了两组：正反断言都要有，降级分支必须同时断言「该降级时降级」和「该走正向时走正向」。
- **CommonJS 测试脚本不能有顶层 `await`**，否则 Node 报 `ERR_AMBIGUOUS_MODULE_SYNTAX`。
  要等异步，用 `new Promise(r => setImmediate(r)).then(fn)` 把后续串成 Promise 链。
- **`setImmediate` 是排空微任务队列的钥匙**：上一组遗留的在途写会污染下一组的 `pendingWrites`，
  必须在两组之间让出事件循环，计数才会归零。
