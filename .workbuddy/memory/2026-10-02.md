### ⚠️ 本轮最重要的发现：Batch 1 造出 5 个「点了没反应」的按钮

Batch 1 抽了 6 个组件后，`arch-check` 报「✓ 与基线等价」、274/214/107 全绿 —— 但**按钮是死的**：

| 位置 | WXML 里的绑定 | 组件 js 里的方法 | 页面侧 |
|---|---|---|---|
| `fq-appbar` 齿轮 | `onGotoMine` | `onMine` ✗ | `bind:mine="onMine"`，而页面里根本没有 `onMine`（有 `onGotoMine`）✗ |

| `fq-bottombar` | `onNewHere` | `onNewHere` ✓ | ✓ —— 6 个里唯一接对的 |

**根因**：抽取器把 WXML **逐字**搬走（连 `bindtap="onX"` 一起），而组件的 `js` 是**手写**的。

**这一类失败当时一条检查都没有**：`arch-check` 管「渲染结果」，逻辑仿真只覆盖拖动/左滑，
两者之间正好漏掉「按钮点了会不会有事」。**新增一类文件/一层间接时，必须问：
「哪条既有检查现在成了盲区？」**

### 新增 `event-check.js`：五条契约

- **A 组件自带**：组件 WXML 每个 `bind/catch` 的方法必须在**该组件 js** 里有定义。
- **B 页面自带**：页面 WXML 每个 `bind/catch` 的方法必须在**页面 js / drag.js** 里有定义。
- **C 出口闭合**：组件 `triggerEvent('x')` 必须有人 `bind:x`；页面 `bind:x` 也必须真有组件在发。
- **D 取值形状**：组件带 detail 发的事件，页面 handler 必须读 `e.detail`。
- **E 同名同形**：两个组件发同名事件时形状必须一致，否则「该不该读 `e.detail`」没有唯一答案。

五条**逐条做过变异测试**，都能红。

**修法（也是约定）**：组件内部 handler **保留页面原来的方法名**（WXML 是逐字搬来的，
不该反过来改它），对外用 `triggerEvent` 换成自己的事件名。
页面 handler 若只有一个来源就读 `e.detail.k`；若页面内部也直接绑（如 `onPickCat`）
则两边都认：`e.detail && e.detail.k !== undefined ? e.detail.k : e.currentTarget.dataset.k`。

### 组件化的两条硬约定（写进了每个组件的 js 头注释）

1. **`virtualHost: true`** —— 组件不产生额外节点。必须：`.screen` 是纵向 flex，
   各固定块靠 `flex: 0 0 auto` 占高度；组件一旦变成真实 flex item，布局就靠运气了。
   （官方文档：虚拟化后「flex 可以放进自定义组件内」。）
2. **`styleIsolation: 'apply-shared'`** —— `app.wxss` 的共享资产能进组件。
   **已查官方文档确认**：默认情况下「除继承样式外，`app.wxss` 中的样式对自定义组件无效
   （除非更改组件样式隔离选项）」，而 `apply-shared` / `addGlobalClass: true`
   的官方示例正是「app.wxss 定义 `.red-text`、组件模板直接用它」。
   所以 Batch 1 把整套自绘图标上提到 `app.wxss` 是成立的。

### 定性的关键一步：先分清「没渲染」还是「渲染了不可见」

肉眼估计不可靠，直接写了个**纯 Node 的 PNG 解码器**（`zlib.inflateSync` + 逐行反滤波）量截图行剖面。
⚠️ 第一版被**手机边框与刘海的深色像素**污染（整幅图连成一段），要先按列统计、把「几乎整列深色」的列当边框排除。

量出来的结果（513×1151，iPhone 390×844）：

| 区域 | 像素行 | 占比 |
|---|---|---|
| 标题 + 元信息 | 73~122 | 6%~11% |
| 统计条 | 146~204 | 13%~18% |
| 「矩阵按…」提示行 | 229~241 | **20%** |
| **y 242~876 空白（0 个文字行）** | — | 21%~76% |
| FAB / 底栏 | 877~1150 | 76%~100% |

**判据**：提示行紧贴在统计条下方（20% 处）。若矩阵只是**丢了颜色**，它仍占
`476rpx × 2 = 483pt`，提示行会被推到 62% 处 —— 所以 `<fq-quad>` 的**节点高度是 0**。
分类条同理（标题与统计条之间只有 24px＝18pt，装不下 45.8pt）。

**「占位但不可见」与「根本没渲染」修法完全不同，必须先分开。**
（顺带排除了「app.wxss 没进组件」这条假设：底栏图标只定义在 `app.wxss`，它渲染正常 → `apply-shared` 有效。）
