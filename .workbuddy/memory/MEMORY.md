# 三、改码纪律（先看这条）

**① 同一条消息里不要对同一个文件发两个编辑。** 两次「读—改—写」会并发，后写的覆盖先写的，
**而工具两次都返回成功**。改同一文件**一次一处、逐个确认**；收尾用「特征字符串扫描」复核落盘。

**② 校验器自己也会骗人**（推导在 `MEMORY-ARCHIVE`）：**跳过条件要显式声明依赖**，别靠「参数够不够多」猜
（`check-all` 曾因此把三个仿真**静默全跳过**还输出绿灯）；**改了被检查器当「锚点」的字符串，检查会静默跳过
而不是报错**（`mp-check` 靠 `indexOf('<scroll-view class="scroller"')` 定位固定头部区间）；
**拿没剥注释的源码去匹配 = 两头都错**（注释能满足掉的检查等于没有检查，注释里抄一句已不存在的标识符又会
**制造假警报**）；**满是假警报的检查比没有检查更糟**；**变异验证要逐条跑**（既可能是断言没守住东西，
也可能是**断言自己写错了**，实测抓到过后者）；**反向对照必须成对做**（只删检查器里的守卫、
却不在源码里放「地雷」，得到的是**假的绿**）。

**③ 新增检查的顺序不能反**：① 跑基线确认绿；② 逐条做变异确认会红。**永远绿的测试等于没有测试。**

# 四、尺寸与样式（改 CSS 前必读）

★ **全文 13 条在 `MEMORY-OPS.md` §九** —— 动手前先去读。这里只留最会咬人的 6 条：

1. **设计稿 px × 2 = rpx**（画布 375px）；**1rpx = 截图宽 ÷ 750**。⚠️ `box-sizing:border-box` 全局 →
   所有 `height` 都是**含 padding 的总高**。
2. **固定高度两处成对改**：`index.wxss` 顶部常量表 ↔ `utils/const.js` 的 `LAYOUT`（导航 88 / 分类条 88 /
   统计条 112 / Tab 120 / 底栏 134）；拖动成对：`ROW_GAP 16` ↔ `.row{margin-bottom}`，
   `SWIPE_W 240` ↔ `.rowacts .act` 宽 120×2。
3. **禁止用 JS 算滚动区高度**（Android `screenHeight` 含虚拟导航条），`LAYOUT` 不参与运行期计算。
   **凡是「算出来的 px」都值得怀疑：先问能不能改成 flex + 常数偏移。**
4. **安全区不能与固定 `height` 同元素**（border-box 会把它从 `height` 里抠掉）；**要等分必须清 `min-width:auto`**；
   **flex 间距用 `margin-right`**（`gap` 只留给 grid）；**单行居中用 `height` + 等值 `line-height`**。
5. ⚠️ **不要给滚动容器里「静止的元素」挂 `transform` 或裁剪**：会被提升成独立图层 → 长列表滚动出现
   「整块不绘制」的白洞（数据 / 高度全对，静态检查抓不到）。位移改**条件渲染**（静止写 `none`）；
   裁剪只挂真需要的那一行（`.row.sw`）。
6. ⚠️ **共享控件只定「规格」，策略留给宿主**（v7）：`.wtrack` 那一套上提 `app.wxss` 后，
   `touch-action` 与 `overflow` **一律不写** —— 前者在长列表里造成「按着滑不动」的死区，
   后者会裁掉圆点在 0% / 100% 时「到头了」的悬空提示。

# 五、布局：固定头部 + 总览 / 日程一屏装满

`.screen` 是纵向 flex，中间 `flex:1;min-height:0` 吃掉剩余高度：detail/all/mine 用 `<scroll-view class="scroller">`；
**overview 不套滚动容器**（用 `.ovbody`）；**sched 日历固定 + 主体独立滚动**（`.schedwrap`）。

| 视图 | 固定头部（写在滚动容器之前） | 主体 |
|---|---|---|
| detail | `dhead` → `filters` → `sortrow` → `.swipecue` | `.rows-wrap` |
| all | （appbar 在外）→ `sortrow` → `.swipecue` | `.sec` |
| overview | `appbar` / `catsrow` / `stats` | `.ovbody`（不滚） |
| sched | `appbar` + `.schcal` | `.schbody` |

- **每个固定块必写 `flex:0 0 auto`**（默认 `0 1 auto` 会被 `flex:1` 的主体挤扁）；`mp-check.js` 第 4 条拦
  「头部又被写回滚动区」（这类回归语法完全合法，只能靠契约拦）。
- **提示行与它上面那行左对齐**：detail/all 的 `.swipecue` 挂 `.left`；**总览页矩阵说明不挂，保持居中**（语义不同）。
- **总览页一屏装满**：矩阵高度**不写死** —— `.ovgrid{flex:1}` + `.grid.fill .q{height:calc(50% - 7rpx)}`，
  屏幕变矮矩阵跟着变矮，**永远不会冒出滚动条**。动它之前先问：是不是又写死了？
- ⚠️ **挂在这块 flex 区域里的绝对定位元素，参照系必须是它本身**：`fq-fab` 靠 `.ovgrid{position:relative}`
  让 `right:24rpx;bottom:22rpx` 成为「距矩阵右下角」的常数。组件是 `virtualHost`、没有自己的节点，
  少了那句 `relative`，`.fab` 会一路找到 `.screen`（`fixed`）上去 —— 又变回「距屏幕底」。

# 七、数据流

`this.cats`/`this.items` 是服务端数据的内存镜像（**不在 `data` 里**）；`this.plans`（日程）形状是
**`{'YYYY-MM-DD': text}` 映射**而非数组。`Page.data` 只放视图模型。改数据 → 先改镜像 → `render()` 推视图模型
→ 异步落库；失败走 `commit()` 里的 `load()` 回滚。派生方法都叫 `buildXxx()`。
**服务端数据一律「整体重建」而非「增量合并」**（否则服务端的删除会在本地留幽灵）；
⚠️ 新字段**必须容忍旧云函数**（`if (!list) return`），否则用户没重新部署云函数时首屏就被清空。

# 八、云函数 fqTodo —— 必须记住的三件事

## 8.1 ⚠️ 铁律：`fid` 只能由服务端推导

**这是全项目唯一会出安全事故的地方。** 云函数用管理员权限、**绕过数据库安全规则** ——
「集合权限设成仅创建者可读写」这道防线对云函数形同虚设，真正的防线全在代码里：

- 每个 action 第一步 `ensureFamily(OPENID)` 从 `fq_members` 反查 `fid`，到不了就 fail closed；
- 所有 where 用 `{_id: id, fid: ctx.fid}` 双条件，**没有一处从入参取 `fid`**；
- 分权也在服务端：`clearAll` / `genInvite` / `renameFamily` 校验 `fam.ownerOpenid === openid`
  （客户端藏入口只是体验，不是防线）。

**谁把 `fid` 改成客户端传参，就等于把全部家庭的数据敞开。** 第 [12] 组专钉这条。

## 8.2 协议版本握手（FN_VER）

两端各一份 `FN_VER`，**必须始终相等**（当前 **7**），常量在 `utils/const.js` ↔ `cloudfunctions/fqTodo/index.js`。
历史：v3 共享家庭 / v4 分类删改 / v5 提醒推送 / v6 日程计划 / **v7 事项进度**。
`bootstrap` 返回 `fnVer` + `actions`；`load()` 交给 `checkFnVer(data)`，不一致就首屏弹「云函数版本过旧」+ 部署步骤。
**约定：改 action 清单（现 19 个）→ 两端 `FN_VER` 一起 +1，`WRITE_ACTIONS` 同步加。** 第 [17] 组读两份源码比对。
⚠️ **没有新增 action 也照样 +1** —— 版本号钉的是「云端认不认得客户端发过来的字段」。v7 就是这么来的：
进度条一个 action 都没加，但旧云函数不认识 `progress`（白名单写法会把它悄悄丢掉）。
⚠️ **测试里别再写死版本号数字**，从源码读。

## 8.3 排序语义

# 九、手势契约

| 手势 | 结果 |
|---|---|
| 卡片横向滑动（非排序模式） | 左滑露出 2 个操作（240rpx）：未完成 → 完成/删除；已完成 → 撤销/删除（撤销 = `toggleDone` 取反） |
| **卡片底部进度条横向拖动**（非排序模式） | 圆点跟手，**松手才落库**；拖到 100% 即完成，拖回来即自动撤销。**按住轨道任意位置点一下**，圆点直接跳过去 |
| 点卡片（非排序模式） | 进编辑抽屉；若该行正滑开着，这一下只收起 |
| 点「调整顺序」 | 进排序模式：只允许拖**手柄**，其他按钮全锁；震动 + 卡片抖一下；**列表照常滚动** |
| 按住**手柄**拖动（仅排序模式） | 位移 > 5px 拿起，纵向换位，松手落库；不震不抖 |
| 在卡片**本体**上纵向滑（仅排序模式） | 就是滚列表 |

- ⚠️ **纵向手势（拖动 / 滚动）正解是「分元素」，不是「分时机」**：`.dh` 用 `catchtouch*` 截走事件，
  卡片本体保持 `bind`。手柄误用 `bind` → 边滚边拖；本体误用 `catch` → 列表滚不动。第 [15] 组钉死。
- ⚠️ **横向手势有两个（左滑 / 拖进度），只会判给先到的一方 —— 也必须「指定胜者」**：`.prog` 用
  `catchtouchstart`（挡左滑）+ `catchtap`（挡进编辑，`onProgTap` 是**有意为空**的事件屏障）+ `bindtouchmove`
  （放过纵滑给 `scroll-view`）。`touchmove` 若改成 `catch`，每张卡片底部就多一条 48rpx 高、**按着滑不动**的死区。
- **`scroll-y` 常开**，任何模式都不动它（视图层在 touchmove 那刻先启动滚动，`setData` 关得晚半拍）。
- **实现要点 → `MEMORY-OPS.md` §六，动手前必读**：拖动引擎（漏清 `_dgP` 会造成**僵尸拖动**，只在真机复现）
  + 左滑（「滑开才渲染」）。

# 十、事项进度条（v7）

每个事项卡片底部一条进度条。**它和「完成」不是两个状态，是同一条状态线的两种读法** ——
拖到 100% 就是完成，从 100% 拖回来就是自动撤销。

- ⚠️ **耦合钉在云函数 `updateItem` 里，客户端说了不算**：`done` 与 `progress` **任一个进来都会同时定下另一个**；
  两个都传且矛盾时**以 `done` 为准**；落库再统一修正（`done` 真 → `progress` 落 100，否则落被夹到 0–99 的值）。
  ⚠️ `bulk` 的 `markAllDone` 走批量路径，**是最容易漏的口子**（漏了会出现一批「已完成但进度 0%」的行）。
- ⚠️ **客户端 `patch` 只送一个字段**：左滑「完成/撤销」只送 `{done}`，拖进度只送 `{progress}`。
  两个都送 = 两个真相来源，迟早对不上。
- **旧数据回落**：`progress` 缺失时读 `done ? 100 : 0`（唯一读点 `itemPct()`），不是 `undefined`。
- **颜色**：`--wt` 由宿主注入 —— `.prog` 定 `var(--qc, var(--ink3))`（进行中 = 所属象限色），
  `.prog.full` 换 `var(--ok)`。⚠️ **绿只上图形，不上文字**：完成绿对白只有 **3.37:1** ——
  够图形门槛 3:1、**跌破正文门槛 4.5:1**，所以 100% 时读数区把数字换成对勾，而不是把「100%」染绿。
  **读数区固定 68rpx**：`9%` → `100%` 位数变化不许把轨道左右推挤（换对勾后仍占同样宽度）。
- **拖动中只走单行路径 `setData`**（`rows[i].pct` / `sections[j].rows[i].pct`），**不走 `render()`**。
  ⚠️ 两个视图共用同一个模板却落在**两棵不同的数据树**上，`progPath()` **只看当前视图那一棵**；
  两棵都扫的话切视图那一瞬可能同时命中同一个 id，表现是「数据对了、屏幕没动」。
  **松手才落库**（每帧发一次 = 几十个并发请求，且可能乱序到达）。
- ⚠️ **`progPctAt(rect, x)` 的 `rect` 必须由调用方传进去**：`onProgEnd` 落库前会先清 `this._pg`，
  自己去读会**整条静默失效**（「点一下圆点跳过去」不报错、不落库、进度不动，看着像没点到）。
  这个 bug 是写测试时抓到的，不是想出来的。
- **纵滑永久放弃本次手势**（`|dx| <= |dy|` 即认输）；**排序模式下不响应触摸，但照旧 `catch` 掉事件**。
★ **实现细则、手势状态机、测试与像素验收数字 → `MEMORY-OPS.md` §十一**。

# 十一、日程版块（v6，2026-10-09）

「今天将要干什么 / 明天准备干什么」。**手写日历不引第三方**（本项目无 npm 构建链）。
★ **结构与实现细节在 `MEMORY-OPS.md` §八**，这里只留会咬人的不变量：

- **入口是第 2 个 Tab**，视图名 `sched`，走内存状态机；编辑**复用现有底部抽屉**（`sheetKind==='plan'`）。
- ⚠️ **页眉那行小标题固定显示「今天」**，**不跟选中日走**；只有 `.dayh` 是「我在看哪天」。
  ⚠️ 验证必须选**非今天**的日期：用今天验，「跟着选中日走」这个错误实现照样绿。
- ⚠️ **所有日期运算走本地零点**：绝不 `new Date('YYYY-MM-DD')`（iOS 按 UTC 解析退一天）、
  绝不 `toISOString()`（UTC，晚 8 点后算到第二天）；工具在 `utils/format.js`。
  「今天 / 明天」标签由 `dayDiff` 推，**绝不写死**。
- ⚠️ **圆点与「这天的事项」必须同口径**（都由 `dayKey(remindAt)` 归堆；items **没有**日期字段），
  否则出现「有圆点但列表空」。列表**不吃分类筛选**。
- **月历固定 42 格（周一起始）**。⚠️ 表头用 `WEEK_MON`，**不要用 `WEEK`**（那个按 `getDay()` 的 0=周日 排，会错开一列）。
- **计划按人存**（`fq_plans`，唯一键 `(fid, _openid, date)`）：家人写同一天**不能互相覆盖**；
  `clearAll` **只清调用者自己的**；日期键只能 `'YYYY-MM-DD'`，服务端字符级校验。

# 十二、诊断手法：UI 像素级 bug 先量截图，别猜

**最关键的：找一个「同族但没被污染」的元素做对照**（桶盖正常 / 桶身跑偏 → 锁定「class 重名」）。
量法、无 PIL 时的纯 Node PNG 解码、Edge 无头截图的坑 → **`MEMORY-OPS.md` §七**。

⚠️ **布局 bug 的验收必须让「错的那个状态」出现在画面上**：日程页眉要选**非今天**的日期，
悬浮按钮要量**和饮水卡有没有重叠**，进度条要**完成态与进行态并排**量。
用默认状态截图，这些 bug 都看不出来 —— 它们只在特定状态下才存在。
