# 二、组件分层（★ 全文 → `MEMORY-OPS.md` §十三）

**×13** 展示型组件（`index.json` 注册表为准）+ `utils/{const,format,drag}.js` + `services/cloud.js`。

# 三、改码纪律（先看这条）

**① 同一条消息里不要对同一个文件发两个编辑。** 两次「读—改—写」会并发，后写的覆盖先写的，
**而工具两次都返回成功**。一次一处、逐个确认；收尾用「特征字符串扫描」复核落盘。

**② 校验器自己也会骗人**：跳过条件要**显式声明依赖**（`check-all` 曾把三个仿真静默全跳过还输出绿灯）；
改了被当「锚点」的字符串，检查会**静默跳过而非报错**；**拿没剥注释的源码匹配 = 两头都错**；
**满是假警报的检查比没有检查更糟**；**变异验证要逐条跑**；**反向对照必须成对做**（否则是假绿）。

**③ 新增检查的顺序不能反**：① 跑基线确认绿；② 逐条变异确认会红。**永远绿的测试等于没有测试。**
⚠️ 把①**做成变异脚本开头的守卫**（基线不绿就退出并回显输出）—— 靠记性必然漏（10-14 实测：基线是红的却
照样跑完，「16/16 全红」成了自我欺骗）。**纪律要机器化，不能只写在文档里。**

**④ 断言必须检验「它声称检验的东西」**（v9 实测）：「改周期要复位 `pushed`」那条配的是「每天 + 提前 30 天」，
而**夹取**本身就让提前量变了 —— 实现漏掉 `repeat` 的比较，`pushed` 照样被复位，断言假绿；补一条「提前量取 60、
不触发夹取」才钉得住。⚠️ **夹具里每个枚举值都得是白名单内的**（v9 传 `leadMin: 3`，被 `toLead` 静默回落成 30）。

# 四、尺寸与样式（改 CSS 前必读）

★ **13 条全文 → `MEMORY-OPS.md` §九**。最会咬人的 5 条：

1. **设计稿 px × 2 = rpx**（画布 375px）；**1rpx = 截图宽 ÷ 750**。⚠️ 全局 `border-box` ⇒ 所有 `height`
   都是**含 padding 的总高**。
2. **固定高度两处成对改**：`index.wxss` 顶部常量表 ↔ `utils/const.js` 的 `LAYOUT`（导航 88 / 分类条 88 /
   统计条 112 / Tab 120 / 底栏 134）；成对的还有 `ROW_GAP 16` ↔ `.row{margin-bottom}`、
   `SWIPE_W 240` ↔ `.rowacts .act` 宽 120×2。
3. **禁止用 JS 算滚动区高度**（Android `screenHeight` 含虚拟导航条）。**凡是「算出来的 px」都值得怀疑。**
   另外：**安全区不能与固定 `height` 同元素**（border-box 会把它抠掉）；**要等分必须清 `min-width:auto`**；
   **flex 间距用 `margin-right`**（`gap` 只留给 grid）。
4. ⚠️ **不要给滚动容器里「静止的元素」挂 `transform` 或裁剪** → 提升成独立图层 → 长列表出现「整块不绘制」
   的白洞（数据 / 高度全对，静态检查抓不到）。位移改**条件渲染**；裁剪只挂真需要的那行（`.row.sw`）。
5. ⚠️ **共享控件只定「规格」，策略留给宿主**（v7）：`.wtrack` 上提 `app.wxss` 后 `touch-action` 与 `overflow`
   **一律不写**（前者造成「按着滑不动」的死区，后者裁掉 0% / 100% 的悬空提示）。

# 五、布局：固定头部 + 总览 / 日程一屏装满

`.screen` 纵向 flex，中间 `flex:1;min-height:0` 吃掉剩余高度：detail/all/mine 用 `<scroll-view class="scroller">`；
**overview 不套滚动容器**（`.ovbody`，不滚）；**sched 日历固定 + 主体独立滚动**（`.schedwrap`）。
固定头部（写在滚动容器**之前**）：detail = `dhead` / `filters` / `sortrow` / `.swipecue`；all = `sortrow` /
`.swipecue`；overview = `appbar` / `catsrow` / `stats`；sched = `appbar` + `.schcal`。

- **每个固定块必写 `flex:0 0 auto`**（默认 `0 1 auto` 会被 `flex:1` 的主体挤扁）；`mp-check.js` 第 4 条拦「头部
  又被写回滚动区」—— 这类回归语法完全合法，只能靠契约拦。
- **提示行与上面那行左对齐**：detail/all 的 `.swipecue` 挂 `.left`；**总览页矩阵说明不挂，保持居中**。
- ⚠️ **总览页一屏装满**：矩阵高度**不写死** —— `.ovgrid{flex:1}` + `.grid.fill .q{height:calc(50% - 7rpx)}`，
  屏幕变矮矩阵跟着变矮，**永远不冒滚动条**。动它前先问：是不是又写死了？
- ⚠️ **挂在这块 flex 区域里的绝对定位元素，参照系必须是它本身**：`fq-fab` 靠 `.ovgrid{position:relative}` ——
  组件 `virtualHost` 没有自己的节点，少了那句 `relative`，`.fab` 会找到 `.screen`（`fixed`）→「距屏幕底」。

# 七、数据流

`this.cats`/`this.items` 是服务端数据的**内存镜像**（**不在 `data` 里**）；`this.plans`（日程）形状是
**`{'YYYY-MM-DD': text}` 映射**而非数组。`Page.data` 只放视图模型。改数据 → 先改镜像 → `render()` 推视图模型
→ 异步落库；失败走 `commit()` 里的 `load()` 回滚。派生方法都叫 `buildXxx()`。
**服务端数据一律「整体重建」而非「增量合并」**（否则服务端的删除会在本地留幽灵）；
⚠️ 新字段**必须容忍旧云函数**（`if (!list) return`），否则用户没重新部署云函数时首屏就被清空。

# 八、云函数 fqTodo —— 必须记住的三件事

## 8.1 ⚠️ 铁律：`fid` 只能由服务端推导

**全项目唯一会出安全事故的地方。** 云函数用管理员权限、**绕过数据库安全规则** ——
「集合权限设成仅创建者可读写」对云函数形同虚设，真正的防线全在代码里：

- 每个 action 第一步 `ensureFamily(OPENID)` 从 `fq_members` 反查 `fid`，到不了就 fail closed；
- 所有 where 用 `{_id: id, fid: ctx.fid}` 双条件，**没有一处从入参取 `fid`**；
- 分权也在服务端：`clearAll` / `genInvite` / `renameFamily` 校验 `fam.ownerOpenid === openid`
  （客户端藏入口只是体验，不是防线）。

**谁把 `fid` 改成客户端传参，就等于把全部家庭的数据敞开。** 第 [12] 组专钉这条。

## 8.2 协议版本握手（FN_VER）

两端各一份 `FN_VER`，**必须始终相等**（当前 **9**）：`utils/const.js` ↔ `cloudfunctions/fqTodo/index.js`。
历史：v3 家庭 / v4 分类删改 / v5 提醒推送 / v6 日程 / v7 进度 / v8 提前量 / **v9 周期**。
`bootstrap` 返回 `fnVer` + `actions`；`load()` 交给 `checkFnVer(data)`，不一致首屏弹「云函数版本过旧」+ 部署步骤。
**约定：action 清单（现 19 个）变了 → 两端 `FN_VER` 一起 +1、`WRITE_ACTIONS` 同步加**；第 [17] 组读两份源码比对。
⚠️ **没有新增 action 也照样 +1** —— 版本号钉的是「云端认不认得客户端发过来的字段」。v7 / v8 / v9 都没加 action，
但旧云函数不认识 `progress` / `leadMin` / `repeat`（白名单写法悄悄丢掉）：v8 =「选好的提前量重进一次变回 30 分钟」，
v9 =「选了每天提醒，第二天就再也不响」。⚠️ **`fqRemind` 不在 action 清单里、握手管不到它** —— 改提醒链路要自己
单独重新部署（v8 / v9 都必须）。⚠️ **测试里别再写死版本号数字**，从源码读。

## 8.3 排序语义

**粒度是「象限 × 分类」**；**落库整段重写成 `0/10/20…`**（`ORDER_STEP=10`），只把 `order` / `quad` 真变了的
行发给 `reorder`。⚠️ **不要改成「相邻取中值」**（反复拖动会把浮点间距耗光）；**换位判定留容差 `EPS = 0.5`**；
**筛选下只重排可见项**（`visibleIdx(full)` 映回完整下标再 splice）。

# 十、事项进度条（v7）

**「完成」与进度条是同一条状态线的两种读法** —— 拖到 100% 就是完成，拖回来就是自动撤销。

- ⚠️ **耦合钉在云函数 `updateItem` 里，客户端说了不算**：`done` 与 `progress` **任一个进来都会同时定下另一个**；
  两个都传且矛盾时**以 `done` 为准**；落库统一修正（`done` 真 → 100，否则落被夹到 0–99 的值）。
  ⚠️ `bulk` 的 `markAllDone` 走批量路径，**是最容易漏的口子**（会出现一批「已完成但进度 0%」的行）；
  ⚠️ **客户端 `patch` 只送一个字段**（左滑只送 `{done}`、拖进度只送 `{progress}`），两个都送 = 两个真相来源；
  **旧数据回落**读 `done ? 100 : 0`（唯一读点 `itemPct()`）。
- ⚠️ **绿只上图形，不上文字**：完成绿对白只有 **3.37:1**（够图形门槛 3:1、**跌破正文 4.5:1**），所以 100% 时
  读数区把数字换成对勾而不是染绿；**读数区固定 68rpx**（`9%` → `100%` 不许左右推挤轨道）。`--wt` 由宿主注入。
- ⚠️ **拖动中只走单行路径 `setData`**（`rows[i].pct` / `sections[j].rows[i].pct`），**不走 `render()`**；**松手才落库**。

  会同时命中同一个 id → 「数据对了、屏幕没动」）。

# 十一、提醒：提前量（v8）与周期（v9）

每条事项各带**一个提前量**（10 档 + 「不提醒」，**默认 30 分钟**）与**一个周期**（只提醒一次 / 每天提醒，
**默认只一次**）。★ 全文 → README §十二；实现细则 v8 §1.4.1 / **v9 §1.4.2** → `MEMORY-OPS.md`。踩过的坑：

- ⚠️ **`pushAt` 必须预计算落库**（逐条提前量**表达不成单一扫描窗口**，放宽窗口再内存过滤会撞 `fqRemind` 的
  `CAP = 500` → **静默漏推**）：`pushAt = remindAt - leadMin × 60000`，`fqRemind` 只按它扫，索引也从 `remindAt`
  改到它。⚠️ **老数据 `backfillPushAt()` 每轮先回填再扫描**（反了会整批漏掉），判据取 `leadMin: _.exists(false)`。
- ⚠️ **`-1` 是「不提醒」的哨兵，不是「提前 0 分钟」**：`toLead()` 对白名单外的值一律回落默认档；若 `0` 合法，
  一个脏值就把提醒**静默关掉**（最糟的失败方向）。三份白名单逐字相同（`LEAD_OPTIONS` / 两份 `LEAD_ALLOWED`、
  `LEAD_DEFAULT = 30`），`test-remind.js` 读源码比对。
- ⚠️ **`remindAt` / `leadMin` / `pushAt` 是一组**（任一进来三个一起重算），且**「提前量真的变了」也要复位
  `pushed`**，否则那条提醒永远不再排队（「改了没用」，不报错）。**本地镜像也要写 `it.leadMin`**，漏了的表现
  与「云端还是旧包」一模一样。**「不提醒」= 保留提醒时间、只是不发通知**，与「清除提醒时间」是两件事。
- ⚠️ **每天提醒的去重不能靠 `pushed: true`**（它在写入前后**都成立**，两条并发会双双 `updated: 1` 各发一条）。
  改用**拿 `pushAt` 当版本号**，**同一次 update** 里「滚到下一个整天」+「`pushed` 写回 false」。
- ⚠️ **三条路径都要滚**（过期 / 正常 / 发送失败）：`nextAt` 在进分支**之前**算好、统一交给 `claim`。漏一条，
  那条提醒**卡死在原地再也不响**（不报错）。⚠️ **过期的每天提醒不算「未送达」** —— `pushAt` 停在过去是
  **设计内状态**（刚切到每天 / 云函数停过几天），记成 `expired` 会让用户看到一条根本不存在的失败。
- ⚠️ **每天模式提前量夹到 1 天内**（`LEAD_DAILY_MAX = 180`）：「每天」×「提前 30 天」= 连推 30 条同一件事；
  客户端藏档位只是体验，**云端 `toLead(v, repeat)` 再夹一次**，方向是**发得晚**而非不发。⚠️ **「`repeat` 变了」
  要用夹取之后的提前量判定**（同一次请求可能既改周期又留着 30 天档 → 夹到 180），**只改周期也要复位 `pushed`**。
  **清除提醒时间时保留周期**：客户端 `remindAt` 为空时**不送** `repeat`。⚠️ **额度现实**：一次「允许」= 一条
  发送权，**每天提醒每天烧一条** —— 「我的」页放「补充提醒额度」入口。

# 十二、日程版块（v6）
